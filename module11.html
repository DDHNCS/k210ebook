知识活页M11-T1-K1

人脸检测任务与 KPU 视觉能力

约 15 分钟

1. 人脸检测：检测出图片中的人脸并标示位置

人脸检测是检测出图片中的人脸，并能够标示出人脸的位置。人脸检测技术主要完成了两件工作：

第一，判断图片中是否包含人脸区域——图片里有没有人脸？
第二，如果图片中存在人脸，将人脸的位置预测出来——人脸在哪个位置（框）？
注意区分：人脸检测只回答"有没有、在哪里"（本模块）；人脸识别还要回答"是谁"（下一模块）。检测是识别的前提。

2. K210 的机器视觉能力

Kendryte K210 具备机器视觉能力，是零门槛机器视觉嵌入式解决方案，可以在低功耗情况下进行卷积神经网络计算。该芯片可以实现以下机器视觉能力：

能力说明
基于卷积神经网络的一般目标检测检测任意训练过的目标类别
基于卷积神经网络的图像分类任务判断图像属于哪个类别
人脸检测和人脸识别检测人脸 / 识别身份
实时获取被检测目标的大小与坐标输出检测框
实时获取被检测目标的种类输出类别

3. KPU 要点回顾

KPU 是通用的神经网络处理器，可以在低功耗的情况下实现卷积神经网络计算，实时获取被检测目标的大小、坐标和种类，对人脸或者物体进行检测和分类。使用 KPU 时，必须结合 model compiler（模型编译器，如 nncase）。特点回顾：支持定点化模型（网络层数无直接限制）、每层参数单独配置、支持 1×1 与 3×3 卷积、任意激活函数、实时最大参数 5.5MiB~5.9MiB。

记忆锚点：检测 = "有没有 + 在哪里"；K210 五种视觉能力都建立在"KPU 跑 CNN 模型"之上；模型必须先经编译器转成 kmodel。
知识活页M11-T1-K2

模型加载与区域层配置

约 20 分钟

1. kmodel 的两种加载方式（LOAD_KMODEL_FROM_FLASH 宏）

工程用宏 LOAD_KMODEL_FROM_FLASH 控制模型从哪来：

方式宏取值原理
分开烧录1模型烧在 Flash 的 0xA00000 地址：malloc(KMODEL_SIZE + 255) 申请内存 → 255 字节对齐 → w25qxx_read_data(0xA00000, model_data_align, KMODEL_SIZE, W25QXX_QUAD_FAST) 从 Flash 读出
合并编译0（默认）用 INCBIN(model, "detect.kmodel") 把模型二进制直接编进固件，model_data_align = model_data 直接指向固件内数组
工程现状：face_detection 工程默认 LOAD_KMODEL_FROM_FLASH 0，即 detect.kmodel（约 380KB）随代码一起编进 face_detection.bin，烧一个 bin 即可运行。

2. 加载模型：kpu_load_kmodel

kpu_load_kmodel(&face_detect_task, model_data_align)：把 kmodel 数据加载到 KPU 任务句柄 face_detect_task。返回非 0 说明模型加载失败（打印 "model init error" 并死循环）。注意：kmodel 需要与 nncase 配合使用——模型必须先由 nncase 转换。

3. 区域层配置：解码检测框的关键参数

KPU 输出的原始结果是特征图，需要区域层（region_layer）解码成检测框。配置如下：

参数工程取值含义
anchor_number5锚框数量（YOLO 预置框）
anchorg_anchor[10]5 组锚框宽高，如 (0.57, 0.68)、(1.87, 2.06)…(9.77, 9.17)
threshold0.7置信度阈值：概率低于 0.7 的框直接丢弃
nms_value0.3NMS 非极大值抑制阈值：重叠度大于 0.3 的重复框合并
region_layer_init(rl, 20, 15, 30, 320, 240)—区域层网络宽 20、高 15、通道 30，原始图像 320×240
记忆锚点：threshold 管"信不信"（太低误检多、太高漏检多）；nms_value 管"去重"（同一人脸只留一个框）；锚框是模型训练时预置的先验尺寸。
知识活页M11-T1-K3

kfpkg 打包与烧录

约 15 分钟

1. 为什么需要 kfpkg？

.bin 文件是固件内容，作为参数传给烧录软件，软件会默认烧录到 flash 开头，完成后重启即可运行；但是有时候我们需要烧录其它二进制文件到 flash，比如烧录模型、文件系统或者自己定义的其它数据，这时需要指定烧录的地址——光靠 .bin，烧录工具不知道数据要烧到 flash 的哪里。打包一个 .kfpkg 格式文件正是为了实现这个目的。

2. kfpkg 由 3 部分组成

组成部分说明
flash-list.json文本文件，记录 .bin 文件列表及烧录地址等信息
*.bin固件文件
*.*其他文件（二进制文件，如 kmodel）

3. flash-list.json 示例

同时下载 face_detection.bin 固件与 detect.kmodel 模型到 Flash 的 0xA00000 地址：

{
  "version": "0.1.0",
  "files": [
    {
      "address": 0,
      "bin": "face_detection.bin",
      "sha256Prefix": true
    },
    {
      "address": 0x00A00000,
      "bin": "detect.kmodel",
      "sha256Prefix": false
    }
  ]
}

4. 打包步骤与注意

改代码：把 LOAD_KMODEL_FROM_FLASH 改为 1，重新生成 bin（模型从 Flash 0xA00000 读）。
写清单：按上面格式写 flash-list.json，地址要与代码中 w25qxx_read_data 的 0xA00000 一致，否则无法读取模型文件。
打包：把 flash-list.json、face_detection.bin、detect.kmodel 三个文件压缩为 zip，然后修改扩展名为 .kfpkg。
烧录：kflash 直接选择此 kfpkg 文件下载运行程序。
记忆锚点：kfpkg = flash-list.json（地址清单）+ 固件 + 模型；代码里的读取地址必须和清单地址一致。

活动一：流程排序（小组完成）

1人脸检测完成哪两件工作？
答案：①判断图片中是否包含人脸区域；②若存在人脸，预测人脸的位置。

答案：flash-list.json + *.bin 固件 + 其他二进制文件；清单里的地址必须与代码中读取模型的地址一致（如 0xA00000）。
6人脸检测和人脸识别有什么区别？
答案：检测只回答"有没有人脸、在哪"；识别还要回答"是谁"（输出身份特征并匹配）。

int main(void)
{

3. 主流程解读

系统初始化：时钟（PLL0 800MHz / PLL1 400MHz + 使能 AI 时钟）→ 串口 → 引脚映射 → IO 1.8V → 中断初始化。
Flash 初始化：w25qxx_init(3, 0) + 四倍模式；kmodel 两种加载方式由宏控制（默认 INCBIN 合并编译）。
外部硬件：lcd_init + logo 与欢迎语 1 秒 → ov2640_init。
模型加载：kpu_load_kmodel 加载 detect.kmodel；配置区域层（5 锚框、阈值 0.7、NMS 0.3、网络 20×15×30）。
业务循环：等摄像头帧 → kpu_run_kmodel 送图像（DMA5）→ 等 KPU 完成 → kpu_get_output 取结果 → region_layer_run 解码坐标 → 循环 draw_edge 画红框 → lcd_draw_picture 显示。
教材与工程差异：教材示例欢迎语为 "Hello Yahboom!"，本工程源码为定制版 "Hello HNSW!"（其余 "Demo: Face Detect!" 与教材一致）；另外本工程显式 sysctl_clock_enable(SYSCTL_CLOCK_AI) 使能 AI 时钟，且 PLL1 为 400MHz——KPU 跑模型需要更高算力。

1. 从"滤波"到"检测"：两次 KPU 工程的对比

2. ai_done 回调与标志位

ai_done 是 KPU 运算完成的中断回调，只置 g_ai_done_flag = 1；主循环 while(!g_ai_done_flag) 等待——"中断置标志 + 主循环消费"的套路与模块九、模块十一致。

3. kpu_run_kmodel 五参数

kpu_run_kmodel(&face_detect_task, g_ai_red_buf_addr, DMAC_CHANNEL5, ai_done, NULL)：任务句柄（face_detect_task）、源数据地址（摄像头 AI 缓冲）、DMA 通道（5）、完成后回调（ai_done）、回调参数（NULL）。图像数据经 DMA 直接送 KPU，不占 CPU。

4. 区域层解码（region_layer_run）

KPU 输出的 20×15×30 特征数据不是坐标，需要区域层按 YOLO 方式解码：把特征图的每个格子 + 5 组锚框还原出候选框 → 用 threshold=0.7 过滤低置信度框 → 用 NMS=0.3 合并重叠框 → 输出 obj_info_t 结构（obj_number 个 obj，每个含 x1/y1/x2/y2/class_id/prob）。

5. draw_edge 画框

根据 obj_info->obj[index] 的 x1/y1/x2/y2 在显示缓冲中画两条边各 4 像素、另两条边各 8 像素的红色框（颜色 data = color<<16 | color，直接写 uint32 缓冲）；坐标先做边界钳位防止越界。

拓展M11-X1

拓展任务：让人脸检测更好用

选做

完成必学内容后选做，对应修改工程源码、重新编译烧录，体会"调参数 = 调检测效果"。

拓展 1：调检测灵敏度。把 face_detect_rl.threshold 从 0.7 改为 0.5 / 0.9，分别观察漏检与误检的变化，记录三种取值的现象。
拓展 2：调去重强度。把 nms_value 改为 0.1 和 0.6，观察同一人脸出现多个框还是框数量变少。
拓展 3：改画框样式。把 draw_edge(..., RED) 改为 GREEN / BLUE，或修改 draw_edge 里边框粗细的循环次数（4 / 8），观察显示变化。
拓展 4：体验 kfpkg 分开烧录。把 LOAD_KMODEL_FROM_FLASH 改为 1，重新编译，按 K3 活页打包 flash-list.json + bin + kmodel 为 .kfpkg 并烧录，验证从 Flash 读模型的流程。
拓展 5（进阶）：叠加识别信息。思考：本模块的 detect.kmodel 只输出检测框。下一模块人脸识别模型会输出特征向量，把"框 + 特征 + 数据库匹配"组合，就能实现"认得出是谁"——提前思考特征向量怎么存储与比对。
完成标准：至少完成拓展 1-3 中的两个，并在活页空白处记录每种改动的现象；拓展 4-5 可作为小组探究课题。
