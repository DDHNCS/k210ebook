模块十三 · 模型部署-人脸检测（C）

模块十一、十二用的是工程自带的模型，本模块换个玩法：部署公开预训练模型——拿到别人训练好的模型包（kmodel/kfpkg + main.py），换掉 C 程序里的旧模型、复制新模型的锚框、调好阈值与 NMS，让 K210 的人脸检测效果更准、误检漏检更少。

配套课程：图像识别技术（边缘计算 & 机器视觉） 建议学时：2 学时 前置模块：模块一 ~ 模块十二 硬件平台：Kendryte K210 开发板

文件作用

知识活页M13-T1-K2

模型的获取方式

约 15 分钟

获取可供 K210 使用的模型通常有几种途径：

① 使用公开预训练模型：直接使用官方或社区提供的公开预训练模型（如矽速科技、亚博智能等厂商发布的模型），拿来即用。
② nncase 转换：使用 nncase 工具将主流框架（TensorFlow、Caffe、ONNX 等）训练好的模型转换而来。
③ 在线训练平台：在在线训练平台（百度飞桨、MaixHub）上训练并下载模型。
途径特点适合场景
公开预训练模型零训练成本，拿来即用；效果取决于模型质量通用任务（人脸、物体等）快速部署
nncase 转换可部署自己训练的模型；需掌握模型训练与转换自定义类别 / 专用场景
在线训练平台免本地算力，网页训练；需平台账号与数据集无 GPU 的环境快速出模型
记忆锚点：用现成的 → 矽速/亚博公开模型；用自己的 → nncase 转换；没算力 → 百度飞桨/MaixHub 在线训练。

公开模型包解析

约 20 分钟

1. 本模块的公开模型包（face_detect.zip）

文件内容与作用
face_model_at_0x300000.kfpkg公开人脸检测模型打包文件（约 336KB），内含 facedetect.kmodel 与 flash-list.json，模型烧录地址 0x00300000
main.py模型附带的 MaixPy 程序（Python 环境用）；其中 anchors 元组就是本模型配套的锚框值，移植到 C 程序的依据

2. main.py 里的关键信息

# 模型附带的锚框值（5 组，C 程序中 g_anchor 需要换成它）
anchors = (1.889, 2.5245, 2.9465, 3.94056, 3.99987,
           5.3658, 5.155437, 6.92275, 6.718375, 9.01025)
# 初始化 YOLO2：阈值 0.5、NMS 0.3、锚框数 5
kpu.init_yolo2(task, 0.5, 0.3, 5, anchors)
看懂 main.py：init_yolo2 的五个参数 = 任务句柄、threshold 0.5、nms_value 0.3、锚框个数 5、锚框数据——C 程序中对应 face_detect_rl.threshold / nms_value 与 g_anchor 数组。

3. kfpkg 与烧录地址

flash-list.json 记录了模型烧录地址：facedetect.kmodel → 0x00300000。注意：这与模块十一 C 程序里分开烧录模式默认读取的 0xA00000 不同——使用本公开模型时，若用分开烧录，需把 C 程序中 w25qxx_read_data 的地址改为 0x300000（或直接把 kfpkg 里的 kmodel 编进固件）。

记忆锚点：公开包三要素 = 模型（kmodel/kfpkg）+ 程序（main.py）+ 锚框藏在 main.py 里；烧录地址以 kfpkg 的 flash-list.json 为准。

C 程序与模型替换

约 20 分钟

1. 沿用模块十一的 C 语言人脸检测程序

本实验的 C 语言主程序就是模块十一的 face_detection 工程（main.c + region_layer + ov2640 + lcd），它的核心流程不变：加载 kmodel → 摄像头采集 → kpu_run_kmodel 推理 → 区域层解码 → draw_edge 画框。本模块只动两处：模型文件与参数。

2. 第一步：获取并部署公开模型

获取公开模型文件包：拿到 face_detect.zip（通常包含 kmodel/kfpkg 文件和 main.py）。
用 VSCode 打开 C 语言程序：打开 face_detection 工程（模块十一）。
复制模型文件替代原模型：把公开模型的 facedetect.kmodel（或解包 kfpkg）复制到项目文件夹中，替代原有的 detect.kmodel。
两种部署方式：① 直接替换 detect.kmodel 文件名（INCBIN 合并编译进固件，最简单）；② 用 LOAD_KMODEL_FROM_FLASH=1 + kfpkg 分开烧录（模型烧到 flash-list.json 指定的地址，本模型为 0x300000）。

3. 模型加载代码回顾（main.c）

// 合并编译：模型直接编进固件（默认）
INCBIN(model, "detect.kmodel");
// 分开烧录：从 Flash 指定地址读模型
w25qxx_read_data(0x300000, model_data_align, KMODEL_SIZE, W25QXX_QUAD_FAST);
// 加载模型（两种方式共用）

注意：若用分开烧录，读取地址必须与本公开模型 kfpkg 的 flash-list.json 地址一致（0x300000），否则加载不到模型、串口打印 "model init error"。

锚框替换与参数调优

约 20 分钟

1. 第二步：修改锚框值等参数

用记事本或其他编辑工具打开模型附带的 main.py 文件，复制其中的锚框值（anchors）。然后在 C 语言主程序中找到锚框定义的位置（g_anchor），替换以前的锚框值。同时需要设定合适的阈值（threshold）和非极大值抑制（NMS）参数——这两个参数直接影响检测的准确率和漏检率。

3. C 程序中的修改位置

// ① 替换锚框值（以模型 main.py 中的 anchors 为准）
float g_anchor[ANCHOR_NUM * 2] = {1.889, 2.5245, 2.9465, 3.94056,
    3.99987, 5.3658, 5.155437, 6.92275, 6.718375, 9.01025};

4. 调参思路：阈值与 NMS

参数调高调低
threshold漏检增多（只有高置信度才算人脸），误检减少误检增多（低置信度也画框），漏检减少
nms_value同一人脸可能出现多个重叠框（去重弱）相邻的人脸可能被合并（去重过强）
思考题（教材）：阈值设置过高或过低分别会带来什么问题？——过高：真正的人脸被当作低置信度丢弃，漏检；过低：背景/杂物被当作人脸框出，误检。需结合实际效果反复试验取最优值。

③ 为什么单类检测部署这么简单？

人脸检测只有 1 类：region_layer 后处理 classes = channels/5 − 5 = 1，只要框 + 置信度，判断"有没有人脸"即可。因此不需要：类别解码（softmax→argmax）、类别→标签/颜色映射、多分支 switch。这就是它比"多类目标检测"更换模型简单的原因。

④ 关键经验（教材 3.4 实验总结）

  • anchors 必须和模型严格匹配，否则检测失效或效果差——最易踩的坑。
  • threshold / NMS 是调优关键：阈值过高→漏检，过低→误检；NMS 影响重叠框去重。
  • 参数来源：MaixHub 包的 main.py 即"部署说明书"——anchors / threshold / nms_value / max_obj 与 C 参数一一对应，直接换算抄入。

⑤ 部署核对步骤

1 确认新旧模型同为单类 YOLO2 检测结构（大小/输出兼容才能直接换）。
2 替换 kmodel 到工程，改 INCBIN(model, ...)（若从 flash 加载则改加载地址）。
3 从 main.py 取 anchors → 替换 g_anchor[]。
4 设 threshold、nms_value（取自 main.py）。
5 编译烧录，对比新旧检测效果，微调阈值/NMS 至最优。
