模块十四 · 物体分类（图像分类原理与五分类花实现）

前几模块用框标记目标位置（人脸检测、物体检测），本模块换一种任务：图像分类——不画框，只回答"图像里是什么大类别"。K210 运行五分类花模型，对雏菊、蒲公英、玫瑰、向日葵、郁金香实时分类，LCD 显示类别名称与特征值。

配套课程：图像识别技术（边缘计算 & 机器视觉） 建议学时：2 学时 前置模块：模块一 ~ 模块十三 硬件平台：Kendryte K210 开发板
开始学习 查看活页索引

模块总体设计

物体分类 = 基于特征值比对的图像分类技术：KPU 运行分类模型输出一组特征值（各类别概率），取最大值对应类别即分类结果，与"画框定位"的目标检测在概念与应用上明显不同。本模块以五分类花（daisy / dandelion / roses / sunflowers / tulips）为例完成实时分类实验。

图像分类 / 图像识别 / 目标检测的区别

约 20 分钟

三个既有联系又有明显区别的概念

概念含义对数据集的要求
图像分类
Image Classification		用于对图像中特定的对象类别进行分类或预测，主要目的是准确识别图像中的特征，把图像中的各个物体进行分类，如判断图像内容属于猫还是狗精度要求不高，但训练的量更大；只要把图像中特征最明显的对象进行分类即可
图像识别
Image Recognition		识别图中具体的物体是什么，如图中的猫是哪一只猫精度要求要高一些；训练前需要将数据集中的图像进行标注
目标检测
Object Detection		确定目标在给定图像中的位置（目标定位）以及每个目标属于哪个类别（目标分类）；本就是图像分类技术，除了分类还能从自然图像中框出目标的位置精度要求更高，应用场景更复杂；要区别一张图像中不同位置的对象的不同类别
图像分类
什么大类别（猫/狗）
→
图像识别
哪个个体（哪只猫）
→
目标检测
哪里 + 是什么（框出）
记忆锚点：总结来说——图像分类判断"图像里是什么大类别"，图像识别判断"具体的个体是谁"，目标检测则解决"目标在哪里 + 是什么"两个问题。

知识活页M14-T1-K3

五分类花模型的分类原理

约 20 分钟

1. 模型与数据集

"五分类花"模型可以对雏菊（daisy）、蒲公英（dandelion）、玫瑰（roses）、向日葵（sunflowers）、郁金香（tulips）五种花卉进行分类。该模型训练自开源花卉数据集，图片被处理为 224×224 的尺寸输入给 KPU。

索引顺序：分类索引值（0~4）与数据集压缩包中文件夹的顺序一一对应。例如，如果数据集中第一个文件夹是 daisy，那么训练得到的模型中索引值 0 就代表 daisy。这提示我们在制作数据集时必须保持清晰的文件夹命名和顺序，否则会导致分类结果错乱。

2. 分类原理：特征值比对

物体分类的本质是特征值比对。KPU 运行分类模型后，会为输入的图像输出一组特征值（通常是各分类类别的概率或置信度）。程序将这些特征值与一个预先设定的阈值进行比较：高于阈值表示可靠地提取到该类别特征，从而判定图像属于哪个类别。特征值最高的类别被识别为最终分类结果。

输入图像
224×224
→
KPU 推理
分类模型
→
5 个特征值
daisy 0.82 · dandelion 0.05 · …
→
取最大 + 阈值判定
显示 daisy
记忆锚点：分类 = 特征值比对：取最高分类别 + 高于阈值才可信；索引 0~4 与数据集文件夹顺序一一对应。

知识活页M14-T2-K2

关键代码详解

约 20 分钟

1. 阈值与图像缓存（教材核心代码要点）

// 阈值，高于该数值表示提取特征值成功（本工程定制版为 0.7）
#define PROB_THRESH (0.7f)
// 设置图像缓存区：KPU 用 RGB888（3 字节），LCD 用 RGB565（2 字节）
uint8_t *ai_8bit = alloc_ai_buf();
uint16_t *display_buf = (uint16_t*)ai_8bit;
// 加载模型（INCBIN 合并编译）
INCBIN(model, "class.kmodel");
kpu_load_kmodel(&task1, model_data);
教材与工程差异：教材示例阈值 THRESHOLD 0.5；本工程（Yahboom 定制版）为 PROB_THRESH 0.7f——这正是教材"任务二：修改阈值观察稳定性变化"要动手改的数值。

2. 图像缩放与 KPU 推理

// 摄像头图像 320×240 裁剪为 224×224（起点 48, 8），用于 KPU 模型输入
image_crop(&kpu_image, &crop_image, 48, 8);
// 运行 KPU 并获取输出特征值
kpu_run_kmodel(&task1, crop_image.addr, DMAC_CHANNEL5, ai_done, NULL);
kpu_get_output(&task1, 0, &features, &output_size);

3. 特征值比对：argmax 取最大类别

// 比对各特征值，取最大值作为分类结果
size_t cls = argmax(features, 5);
// 分类索引与数据集顺序一致，显示类别名称
switch (cls) {
    case 0: text = "daisy"; break;
    case 1: text = "dandelion"; break;
    case 2: text = "roses"; break;
    case 3: text = "sunflowers"; break;
    case 4: text = "tulip"; break;
}
// 高于阈值才显示分类名（低于阈值视为"不确定"）
if (features[cls] > PROB_THRESH)
    ram_draw_string(display_image.addr, 150, 20, text, RED);
记忆锚点：argmax（取最大索引）+ switch（索引→类名）+ 阈值判定（features[cls] > PROB_THRESH 才显示）；特征值低于阈值时不显示类名，即"识别置信度不足"。

1. 预期实验现象

现象描述：程序运行后，LCD 显示器实时显示摄像头画面。当把不同的花朵放在摄像头前时，屏幕上会显示对应的分类结果（daisy、dandelion、roses、sunflowers、tulips）和特征值大小。切换不同的花朵，分类结果和特征值随之变化。
daisy 雏菊
特征值最大→显示
roses 玫瑰
换花→结果变化
低置信度
低于阈值不显示

2. 任务二：修改阈值观察分类稳定性

把 main.c 中 PROB_THRESH 从 0.7 改为不同值，重新编译烧录，记录分类稳定性变化：

阈值取值现象观察结论
0.3（偏低）容易"乱认"——非花朵/模糊画面也可能超过阈值显示类名（误报多）稳定性下降
0.5介于两者之间，对常见花朵基本可靠居中
0.7（默认）可靠的花朵画面才显示类名，置信度不足时不显示稳定
0.9（偏高）很多花朵识别置信度达不到，LCD 经常不显示类名（漏报多）过于保守
实验结论：阈值设置影响分类的稳定性和准确率——阈值过高漏报多、过低误报多，需要根据训练结果与使用场景调整到最优。
