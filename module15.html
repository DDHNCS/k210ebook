知识活页M15-T1-K2

训练流程：Fork 开源项目与启动训练环境

约 20 分钟

在飞桨平台上训练模型的完整流程

1 登录注册：登录飞桨平台，注册账号，获得赠送的算力。
2 找到训练项目：通过平台提供的链接或标签查找（在"公开项目"中按初级、计算机视觉、机器学习、分类等标签查找）。
3 FORK 项目：点击项目，选择 FORK，创建到自己的项目中。
4 个人中心：点击右上角图标，在个人中心页面可以查看、管理和创建项目。
5 启动环境：点击项目进入运行界面，点击"启动环境"，选择不同的算力进行训练，点击确定启动。
6 替换数据集：运行环境是一个虚拟的 Python 环境。Fork 过来的项目已带数据集作为训练数据，数据存储在 data/ 目录下以压缩包形式存在，可以替换成自己的数据集。
7 执行 cell：按顺序执行 cell 的代码，就能生成 paddle 模型。把鼠标移动到每一个 cell 上，cell 的序号会变成一个运行符号，点击即可运行代码；建议一个一个 cell 向下运行，可以看到每个 cell 的运行结果，当然也可以点击"全部运行"。
8 训练与评估：模型训练 cell 耗时最长——注意此时右侧代码运行的执行灯为绿色，以及 cell 的运行图标变成一个不停旋转的图标，跑完会出现执行完的提示信息；随后对刚训练的模型进行评估。
9 模型转换与下载：为了能在 K210 开发板上运行，cell8-10 对模型进行转换；执行转换代码后会在左边的根目录产生 mobilenet.kmodel 模型。把它下载到本机电脑上，即可引用到 VSCode 工程中等待开发板调用。
特别注意：data 文件夹下文件的目录和文件类型一定要与 cell 里的程序一致。训练自己的模型，重点是训练数据集的整理和文件夹命名规范。
记忆锚点：9 步 = 登录 → 找项目 → Fork → 个人中心 → 启动环境 → 换数据集 → 执行 cell → 训练评估 → 转 kmodel 并下载。data 目录用于存放 / 替换数据集，训练得到的模型可下载引用到 VSCode 中。

训练数据集的准备

约 15 分钟

分类数据集按类别命名文件夹

对于分类任务的数据集，我们需要把要检测的分类物体图片，分别放在以类别名称命名的文件夹中。例如，猫的图片全部放在以 cat 命名的文件夹中，狗的图片全部放在以 dog 命名的文件夹中。

data/
数据集压缩包
→
cat/
猫的图片 ≥50 张
→
dog/
狗的图片 ≥50 张

准备规范

要求说明
图片数量每个类别的图片数量应足够多（建议每个类别不少于 50 张），越多训练出来的模型识别率越高，但训练的时间也相对更长
命名与分辨率图像的命名和分辨率要符合训练平台的要求，图片应尽可能多方面地反映目标的特点

数据集标准化处理

项目 cell 中已经内置了对数据集进行标准化处理的代码（统一尺寸、归一化 mean/std 等），我们只需保证上传的数据集结构与 cell 程序一致，标准化由程序自动完成，不需要手工处理图片。

记忆锚点：一类一文件夹、类名即标签、每类 ≥50 张、命名规范、画面多样化——顺序错乱会让分类结果错乱（沿用模块十四的索引顺序经验）；标准化处理交给 cell 代码，我们负责数据组织规范。

// ① 替换模型文件（五分类花工程中）
INCBIN(model, "model-xxxx.kmodel");  // 原为 class.kmodel

size_t cls = argmax(features, 2);      // 猫狗 2 类：N=2

部署对接检查表（基于五分类花模板）

约 20 分钟

怎么用：训练完拿到新模型的 report.json 后，把它的参数填进"模板值"列，对照右边"你要改的位置"逐项勾选。凡标 必改 的换了模型就要改；标 仅不同才改 的只有和模板不一致才动；标 免改 的不用管。

① 必改项（每次换模型都要核对）

参数模板值（5 类花）新模型值（填）对应改的位置
模型文件class.kmodelmodel-xxxx.kmodelINCBIN(model, "...")
类别数 N5____argmax(features, N) + switch 分支数
类别标签daisy/roses/…按 labels 填，注意顺序switch 里显示的文本（cat/dog…）
判定阈值PROB_THRESH 0.7按训练/实测调PROB_THRESH（可加 CONF_GAP）

② 仅当与新模型不一致才改（先比对 report.json）

参数模板值新模型值（填）若不同要怎么改
输入尺寸[224,224,3]____改 image_crop 偏移（48,8）和 crop 缓冲尺寸/分配
输出张量[1,1,5][1,1,N]读出的 float 个数；argmax 的 N 跟着变

③ 免改 / 提醒（不要被误导去动）

项说明
归一化 mean/std如 123.5 / 58.395 —— 无需改代码，K210 KPU 硬件量化自动处理，裁剪后直接喂 RGB888
摄像头 / DVP / LCD结构不变，除非换了传感器型号
关键踩坑点：① 输出判断 —— out_size = 8 是 2×float（概率，直接比大小）；out_size = 2 是 2×uint8（量化，必须反量化才能得到概率）。② labels 索引顺序必须与 report.json 的 labels[] 一一对应，否则"猫狗对调"。
记忆锚点：必改 4 项（模型/类别数/标签/阈值）；输入输出尺寸先比对 report.json 再动；归一化与摄像头免改。
知识活页M15-T2-K3

二分类的固有现象与演示技巧

约 15 分钟

1. 现象：上电默认显示 "dog" 或 "cat"

猫狗二分类模型烧录运行后，即使镜头前没有任何目标，LCD 上也会显示 "dog" 或 "cat"——这不是程序写错了。

原因：类 softmax 只有两个输出，强制"非此即彼"。对"白墙 / 桌面 / 无目标画面"这类非猫非狗输入，模型也会硬塞一个高置信结果。这是二分类架构的固有现象，不是代码 bug。

2. 正确演示方法

正常识别：上电后直接对准猫 / 狗目标，稳定 2 帧后显示正确标签。
演示"不识别"效果：可以提高阈值到 0.95，或展示快速移动目标（连续帧确认会拒绝），此时不显示类名。
若要求"无目标画面必须空白"：需要重训 3 类模型（cat / dog / background），数据集里加一类"环境图"即可——这是可选项，不是必须。
输入画面二分类（cat / dog）表现说明
猫 / 狗目标稳定 2 帧后显示正确标签正常使用场景
白墙 / 桌面 / 无目标仍显示 dog 或 cat架构固有现象，非 bug
快速移动目标不显示类名（被拒绝）连续帧确认机制
阈值提高到 0.95低置信度不显示类名演示"不识别"效果
记忆锚点：二分类 = 非此即彼（无目标也会硬给答案，属固有现象）；要让无目标画面空白，就加 background 训 3 类。
工作活页M15-T2-W1

部署核对流程（新模型落地 5 步）

约 15 分钟

任务：按 5 步把新模型落到 K210

1 读配置：从飞桨 report.json / 训练配置读：输入维度、输出维度、labels、类别数、mean/std。
2 改必改项：把 ① 的 4 项（模型名/类别数/标签/阈值）填进代码并修改。
3 比对差异项：比对 ②：输入是否仍 224×224、输出张量是否仍与 N 匹配；不同则同步改裁剪/读数。
4 编译烧录验证：编译烧录，看串口 out_size / f0 f1 / raw：确认输出格式与标签映射正确。
5 实测微调：实测多场景，微调 PROB_THRESH 与 CONF_GAP，直到识别率和防误判达标。

快速自检（编译前对一遍）

拓展M15-X1

拓展任务：把训练-部署链路打通

选做

完成必学内容后选做，围绕"数据集、训练、部署"继续探究。

拓展 1：自定义三分类数据集。自己整理三类物体（如手机 / 水杯 / 书本），每类收集 50+ 张照片（不同角度、光照），按规范建文件夹，在飞桨平台上替换数据集训练并部署，验证"换数据即换任务"。
拓展 2：report.json 全字段解读。训练完成后打开 report.json，逐项核对输入维度 / 输出维度 / labels / 类别数 / mean/std，与对接检查表②对照，理解每个字段的用途。
拓展 3：CONF_GAP 实验。在代码中加入类别间置信度差值判断（CONF_GAP）：最高特征值与第二高特征值之差低于 CONF_GAP 时判为"不确定"，观察防误判效果。
拓展 4：输出读数验证。对照踩坑点①，打印串口 out_size / f0 f1 / raw，区分 2×float 与 2×uint8 两种输出格式，验证自己的模型属于哪种并正确读数。
拓展 5（进阶）：完整工程复盘。用 Markdown 整理一份"从数据集到 K210 部署"的完整笔记（数据准备 → 训练 → 转换 → 检查表 → 烧录 → 实测），作为后续自训模型的复用模板。
拓展 6：重训三分类消除"非此即彼"。按 K3 的可选方案，在数据集中增加一类"环境图"（白墙 / 桌面 / 无目标画面），重训 cat / dog / background 三分类模型并部署，验证"无目标画面空白"的效果。
完成标准：至少完成拓展 1-3 中的两个，并在活页空白处记录过程与现象；拓展 4-6 可作为小组探究课题。
