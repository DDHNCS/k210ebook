知识活页M16-T1-K1

K210 两种开发方式的对比

约 20 分钟

1. MaixPy 是什么

MaixPy 是矽速科技公司将 MicroPython 移植到 K210 的项目，支持 MCU 常规操作，用于快速开发具有极低成本和体积实用的 AIOT（人工智能物联网）领域智能应用。

2. 两种开发方式

方式工作原理
C/C++ 方式
（VSCode 环境）		编辑代码后需要编译和调试，验证没有问题后生成 bin 或 hex 文件，然后通过下载器下载到芯片或开发板的 FLASH 中，通电后自动执行代码
Python 方式
（MaixPy 环境）		基于脚本的运行原理，在开发板上构建一个运行环境（刷固件），相当于将 MicroPython 的运行环境移植到开发板上，固件还包括对开发板硬件的支持。Py 文件有两种执行方式：使用 MaixPy IDE 运行，或将程序保存到开发板/Flash 中

3. 优缺点对比

对比项C 方式Python（MaixPy）方式
优点执行效率高、模型加载容量大（可加载约 6MB 模型）开发快速、开源项目多、模型资料丰富，适合快速原型开发
缺点开发周期较长需要一定的 Python 基础；加载的模型大小受限（MaixPy（mini）可加载约 3MB 模型）
记忆锚点：C = 高效 + 大模型 + 周期长；Python = 快速 + 资源多 + 模型小（约 6MB vs 3MB）。
知识活页M16-T1-K2

MicroPython 系统移植

约 15 分钟

1. 系统移植原理

微控制器通常以 C 编程，可以直接访问和控制寄存器来使用外围设备。MicroPython 则集成了这些步骤，可以通过 Python 脚本语言实现硬件底层的访问和控制，比如控制 LED、LCD 显示器、读取电压、控制电机、访问 SD 卡等。

C 编程
直接操作寄存器
→
MicroPython 移植
集成底层步骤
→
Python 脚本控制
LED/LCD/电机/SD 卡

2. 固件（Firmware）是什么

固件：就是写入 ROM（只读存储器）中的程序，担任系统最基础最底层的工作，直接控制硬件，是微处理器上电后第一个启动的程序。固件是与硬件一一对应的，一套硬件方案对应一个固件，否则系统无法正常工作。固件一般由硬件生产厂家提供。

3. 16MB Flash 空间地址规划

刷写成功后，开发板重新启动：有 SD 卡就提示用 SD 卡运行 Python 程序，没有 SD 卡则使用 Flash。注意 16MB Flash 空间的地址规划，通常包括：

区域用途
固件区存放 MaixPy 固件（系统运行环境）
模型区存放 kmodel/kfpkg 模型（如 0x300000）
文件系统区存放 .py 脚本与用户文件（Flash/SD 卡）
记忆锚点：固件 = 底层 + 第一个启动 + 一一对应；Flash 三段 = 固件区 / 模型区 / 文件系统区。

固件烧录步骤

约 15 分钟

准备工作

在刷写固件前，需要准备适配的固件文件（矽速科技官方提供的 MaixPy 固件）和烧录工具（kflash_gui）。本模块配套固件：maixpy_v0.6.2_84_g8fcd84a58_openmv_kmodel_v4_with_ide_support.bin（MaixPy v0.6.2，openmv kmodel v4，带 IDE 支持）。

烧录步骤（6 步）

1 安装驱动：安装 CH340 串口驱动，使电脑能够识别开发板。

3 选择端口：打开 kflash_gui 烧录工具，选择串口端口。

6 点击烧录：点击烧录，等待固件下载完成。
验证：固件下载成功后，开发板将重新启动，并有相应的提示信息。出现开机画面说明固件刷写成功。
注意：若开发板已刷过 C 程序（模块二~十五），本步骤会用 MaixPy 固件覆盖系统区——之后板子按 Python 方式工作；如需回到 C 环境，再烧回原来的 C 固件即可。

MaixPy IDE 的使用

约 20 分钟

1. MaixPy IDE 的安装

从矽速科技官网下载并安装 MaixPy IDE。安装完成后打开 IDE，默认显示 hello world 程序。在 IDE 中可以编写、运行和调试 Python 程序，并通过串口与开发板进行联机交互。

2. MaixPy IDE 的基本操作（4 步）

1 连接开发板：在 IDE 中选择开发板型号（K210），点击左下角"连接"，建立串口连接。
2 运行程序：点击"运行"，IDE 左上角会显示开发板摄像头的实时画面。
3 联机调试：IDE 通过串口与开发板通讯，在 IDE 中可以直接运行程序并查看串口输出。
4 保存程序：为防止串口线松动导致程序中断，可将程序保存到开发板（Flash/SD 卡）中，实现上电自动运行。

3. 屏幕颜色反色问题

注意：由于不同厂商开发板的硬件细微差异，在 MaixPy IDE 中运行程序时，开发板屏幕显示的颜色可能是反的，这是硬件不兼容引起的。需要根据具体开发板进行调整，参考 MaixPy API 手册（https://wiki.sipeed.com/soft/maixpy/zh/index.html），在 LCD 初始化时加入反色设置。
记忆锚点：IDE 四步 = 连接 → 运行 → 调试 → 保存；反色 = LCD 初始化加反色设置（硬件差异所致）。

Python 环境下部署人脸检测模型

约 20 分钟

部署流程（5 步）

1 解压模型包：解压人脸检测模型包（face_detect.zip），获取 kfpkg 文件和 main.py 程序。
2 烧录 kfpkg：将 kfpkg 文件烧录进 Flash。kfpkg 文件指定了模型的烧录地址，也可以直接将 kmodel 文件烧录在指定地址，但同时要保证程序中设定的模型烧录地址与烧录实际地址一致。
3 打开 main.py 并加反色：使用 MaixPy IDE 打开 main.py 文件，在 lcd.init() 中加入颜色反色设置（根据开发板硬件调整）。
4 设定模型地址：设定模型文件存储在 Flash 的 0x300000 位置（可通过注释切换为 SD 卡存储方式）。
5 连接运行：连接并运行程序，在开发板和 IDE 中同时看到人脸检测的效果。

人脸检测的 Python 核心代码

from maix import camera, display, nn
# 加载人脸检测模型：地址 0x300000、阈值 0.5、NMS 0.3
face_detect = nn.YOLO2(0x300000, 0.5, 0.3)
while True:
    img = camera.capture()          # 采集摄像头图像
    faces = face_detect.detect(img) # 运行检测
    for f in faces:
        img.draw_rect(f.x, f.y, f.w, f.h, (255, 0, 0)) # 框出人脸
        img.draw_string(f.x + 3, f.y + 3, "face", (255, 0, 0))
    display.show(img)               # 显示结果
与 C 版本对照：nn.YOLO2 一行 = C 里 INCBIN + kpu_load_kmodel + region_layer_init（锚框/阈值/NMS）；detect() 返回框列表 = C 里回调画框；同一模型（0x300000）两套语言都能跑。
