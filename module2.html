LED颜色硬件引脚（IO）驱动电路点亮条件
LED0红灯IO0（K11 / JTAG TCK）串联限流电阻 R43（1KΩ）低电平

LED 发光原理

约 10 分钟

1. LED 是什么

LED（Light Emitting Diode）即发光二极管，是一种能够将电能转化为可见光的固态半导体器件，它可以直接把电转化为光。因为体积小、功耗低、寿命长，LED 被广泛应用于指示灯、屏幕背光、照明等领域。

2. 内部结构与点亮条件

LED 的内部是一个半导体晶片：晶片的一端附在一个支架上（一端是负极），另一端连接电源的正极，整个晶片被环氧树脂封装起来。只要给正极输入正电压、负极接地，形成回路就可以点亮 LED。

3. 发光的本质：P-N 结

半导体晶片由两部分组成：一部分是P 型半导体（空穴占主导地位），另一部分是N 型半导体（以电子为主）。当这两种半导体连接起来时，它们之间就形成一个 P-N 结。

当电流通过导线作用于晶片时，电子会被推向 P 区，在 P 区里电子与空穴复合，然后以光子的形式发出能量——这就是 LED 发光的原理。

记忆锚点：电子 + 空穴 → 复合 → 发光。光的波长（也就是光的颜色）由形成 P-N 结的材料决定——这就是 LED0（红）与 LED1（绿）颜色不同的根本原因。

FPIOA 引脚映射机制

约 20 分钟

1. 什么是 FPIOA

FPIOA（Field Programmable IO Array，现场可编程 IO 阵列）是 K210 的一大特色：它允许用户将 255 个内部功能映射到芯片外围的 48 个自由 IO 上。也就是说，芯片引脚的"物理位置"和"逻辑功能"是解耦的，由用户按需绑定。

2. FPIOA 支持的能力

可配置能力
  • IO 的可编程功能选择
  • IO 输出的 8 种驱动能力选择
  • IO 的内部上拉电阻选择
  • IO 的内部下拉电阻选择
  • IO 输入的内部施密特触发器设置
  • IO 输出的斜率控制
  • 内部输入逻辑的电平设置

3. 为什么需要引脚映射

K210 的硬件引脚（如 IO0、IO17）是"物理通道"，而程序里操作的软件 GPIO 是"逻辑对象"。程序里操作的都是软件引脚，所以使用硬件 IO 口之前，需要先把硬件引脚映射成软件 GPIO 功能，操作时直接操作软件 GPIO 即可。

硬件引脚
IO0 / IO17（与原理图对应）
→
fpioa_set_function()
完成映射绑定
→
软件 GPIO
GPIO0 / GPIO1（与程序对应）
实验总结要点：K210 芯片使用 FPIOA 可编程阵列，每次使用硬件 IO 口前都需要对硬件 IO 口进行引脚映射；软件中调用的也是映射后的软件 GPIO。
知识活页M2-T1-K4

GPIO 驱动 API

约 15 分钟

1. GPIO 概况

SDK 中对应 GPIO 驱动的头文件是 gpio.h。K210 的通用 GPIO 共 8 个，使用同一个中断源，可配置输入/输出信号，可配置触发 IO 口总中断、边沿触发和电平触发；每一个 IO 都可以分配到 FPIOA 上 48 个管脚之一。

2. 为用户提供的核心接口

API函数原型作用
gpio_init void gpio_init(void) GPIO 口初始化（使能 GPIO 时钟）
gpio_set_drive_mode gpio_set_drive_mode(uint8_t gpionum, gpio_drive_mode_t mode) 设置 GPIO 口输入或输出模式
gpio_set_pin gpio_set_pin(uint8_t gpionum, gpio_pin_value_t value) 设置 GPIO 引脚电平高 / 低
gpio_get_pin gpio_pin_value_t gpio_get_pin(uint8_t gpionum) 读取 GPIO 引脚电平
本实验只用到前三个：先 gpio_init() 使能时钟，再 gpio_set_drive_mode() 设为输出，最后 gpio_set_pin() 控制电平点亮/熄灭。gpio_get_pin() 留待后续按键（GPIO 输入）实验使用。

pin_config.h 配置解析

约 15 分钟

1. 文件作用

由于 K210 使用 fpioa 现场可编程 IO 阵列，允许用户将 255 个内部功能映射到芯片外围的 48 个自由 IO 上，所以把硬件 IO 和软件 GPIO 功能抽出来单独设置，这样更容易理解。整个文件就是三组宏定义：

HARDWARE-PIN
硬件 IO 口，与原理图对应
→
SOFTWARE-GPIO
软件 GPIO 口，与程序对应
→
FUNC-GPIO
GPIO 功能，绑定到硬件 IO 口

2. 完整源码

/**
* @file         pin_config.c
* @brief        硬件引脚与软件GPIO的宏定义
*/
#ifndef _PIN_CONFIG_H_
#define _PIN_CONFIG_H_
/*****************************HEAR-FILE************************************/
#include "fpioa.h"

/*****************************HARDWARE-PIN*********************************/
// 硬件IO口，与原理图对应
#define PIN_LED_0             (0)
#define PIN_LED_1             (17)

/*****************************SOFTWARE-GPIO********************************/
// 软件GPIO口，与程序对应
#define LED0_GPIONUM          (0)
#define LED1_GPIONUM          (1)

/*****************************FUNC-GPIO************************************/
// GPIO口的功能，绑定到硬件IO口
#define FUNC_LED0             (FUNC_GPIO0 + LED0_GPIONUM)
#define FUNC_LED1             (FUNC_GPIO0 + LED1_GPIONUM)

#endif /* _PIN_CONFIG_H_ */

3. 宏含义对照

宏值含义
PIN_LED_00LED0 的硬件引脚号（对应原理图 IO0）
PIN_LED_117LED1 的硬件引脚号（对应原理图 IO17）
LED0_GPIONUM0LED0 的软件 GPIO 编号（程序操作对象）
LED1_GPIONUM1LED1 的软件 GPIO 编号（程序操作对象）
FUNC_LED0FUNC_GPIO0+0LED0 的 GPIO 功能（绑定到硬件 IO0）
FUNC_LED1FUNC_GPIO0+1LED1 的 GPIO 功能（绑定到硬件 IO17）
理解要点：硬件引脚（PIN_）与原理图对应，软件 GPIO（GPIONUM）与程序对应，两者通过"功能"（FUNC_）桥接。改动硬件接线时只改 PIN_ 部分即可，程序其余部分不用动——这就是分层配置的好处。
知识活页M2-T2-K2

main.c 主程序解析

约 20 分钟

1. 完整源码

#include <stdio.h>
#include <unistd.h>
#include "gpio.h"
#include "pin_config.h"

/**
* @brief 硬件初始化，绑定GPIO口
*/
void hardware_init(void)
{
    fpioa_set_function(PIN_LED_0, FUNC_LED0);
    fpioa_set_function(PIN_LED_1, FUNC_LED1);
}

/**
* @brief 主函数，程序的入口
*/
int main(void)
{
    hardware_init();// 硬件引脚初始化

    gpio_init();    // 使能GPIO的时钟

    // 设置LED0和LED1的GPIO模式为输出
    gpio_set_drive_mode(LED0_GPIONUM, GPIO_DM_OUTPUT);
    gpio_set_drive_mode(LED1_GPIONUM, GPIO_DM_OUTPUT);

    // 先关闭LED0和LED1
    gpio_pin_value_t value = GPIO_PV_HIGH;
    gpio_set_pin(LED0_GPIONUM, value);
    gpio_set_pin(LED1_GPIONUM, value);

    while (1)
    {
        sleep(1);
        gpio_set_pin(LED0_GPIONUM, value);
        gpio_set_pin(LED1_GPIONUM, value = !value);
    }
    return 0;
}

2. 逐段解读

代码段作用
#include <unistd.h>提供 sleep() 延时函数（单位：秒）
hardware_init()FPIOA 引脚映射：把硬件引脚 PIN_LED_0/1 绑定为 GPIO 功能 FUNC_LED0/1
gpio_init()GPIO 口初始化，使能 GPIO 时钟
gpio_set_drive_mode(…, GPIO_DM_OUTPUT)把 LED0/LED1 的软件 GPIO 设置为输出模式（使用 GPIO 前必须设置）
value = GPIO_PV_HIGH初始电平取高：LED 高电平熄灭，即"先关闭两个灯"
while(1){ sleep(1); … }死循环：每 1 秒把 value 写给 LED0，同时取反后写给 LED1，实现交替点亮

3. 关键代码逻辑：value = !value

表达式 value = !value 先对 value 取反（高变低、低变高）再赋值：LED0 使用取反前的 value，LED1 使用取反后的 value，两灯电平始终相反——红灯亮时绿灯灭，绿灯亮时红灯灭，从而"交替"。

实验总结要点：① 使用 GPIO 前必须先设置输入/输出模式；② LED 低电平点亮、高电平熄灭；③ K210 程序从 main 函数开始运行。

拓展M2-X1

拓展任务：让 LED 玩出花样

选做

拓展 1：改变闪烁频率

把 sleep(1) 改为 sleep(2) 观察现象变慢；改回 1 秒后，再尝试更快的 0.5 秒间隔（sleep 参数单位是秒，更短的延时可用 usleep(500000)，单位微秒）。思考：灯交替太快会看到什么？

拓展 2：两灯同时亮灭

把 while 循环里第二行改为 gpio_set_pin(LED1_GPIONUM, value);（去掉取反），两灯会同时亮、同时灭。想一想：这对应"呼吸"还是"交替"？再改回原样。

拓展 3：换一个引脚控制外接 LED

用杜邦线在 IO16（或其他空闲 IO）外接一个 LED（串联 1KΩ 电阻到 3.3V），只修改 pin_config.h 中的 PIN_LED_1 为 16，重新编译烧录。验证"硬件引脚与软件 GPIO 解耦"带来的便利。

拓展 4（进阶）：按键控制 LED

利用 gpio_get_pin() 读取按键电平：按下按键时红灯亮，松开时红灯灭。提示：按键引脚需先做 FPIOA 映射，并设置为输入模式 GPIO_DM_INPUT。可参考 SDK 中其他 GPIO 输入示例。

拓展 5（预告）：呼吸灯

让 LED 由暗到亮、由亮到暗循环变化（"呼吸"效果）需要连续调节占空比，这属于 PWM（脉冲宽度调制）的范畴，将在后续模块学习。提前思考：只用 GPIO 高低电平能做到吗？

完成标准：至少完成拓展 1–3 中的两个，并在活页空白处记录每种改动的现象；拓展 4–5 可作为小组探究课题。
