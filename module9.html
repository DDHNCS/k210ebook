模块九 · 摄像头采集数据（OV2640 摄像头与 DVP 接口）

前面模块都在"处理"数据，本模块真正"看见"世界：OV2640 摄像头通过 DVP 数字摄像头接口把画面传给 K210，一帧一帧刷新到 LCD 上实时显示。这是迈向图像识别的关键一步——先有图像，才有识别。

配套课程：图像识别技术（边缘计算 & 机器视觉） 建议学时：2 学时 前置模块：模块一 ~ 模块八 硬件平台：Kendryte K210 开发板

模块总体设计

摄像头输出 → DVP 接口（SCCB 配置 + 中断传输）→ 内存缓冲 → LCD 显示。核心机制：DVP 中断"帧开始 / 帧结束"通知 + 主循环等待帧完成标志刷新画面，实现实时视频显示。

2. OV2640 特性

OV2640 是 Omni Vision 公司生产的一颗 CMOS 图像传感器，支持最高 200 万像素，支持自动曝光控制、自动增益控制、自动白平衡、自动消除灯光条纹等自动控制功能。

3. LCD 特性（回顾）

LCD 显示为 2.0 寸，分辨率为 320×240，驱动芯片是 ST7789，体积小，厚度薄，耗能低，工作电压为 3.3V，显示屏的材料为 TFT。TFT（Thin Film Transistor）是指薄膜晶体管，使每个液晶像素点都是由集成在像素点后面的薄膜晶体管来驱动，从而可以做到高速度、高亮度、高对比度显示屏幕信息。

记忆锚点：摄像头"拍得到"（CMOS 感光），LCD"显示得出"（TFT 逐点驱动），DVP 在中间"传得快"。
知识活页M9-T1-K2

DVP 接口特性

约 15 分钟

1. 什么是 DVP

OV2640 摄像头与 K210 开发板通过数字摄像头接口（DVP）连接，DVP 是常用的摄像头接口模块，具有以下特性：

a. SCCB 配置：支持 SCCB 协议配置摄像头寄存器（SCCB 与 I2C 类似，是 OmniVision 的配置总线）。
b. 分辨率：支持 640×480（30 万像素）及以下分辨率，每帧大小可配置。
c. 图像格式：支持 YUV422 和 RGB565 格式的图像输入。
d. 双路输出：支持图像同时输出到 KPU 和显示屏：输出到 KPU 的格式可选 RGB888，或 YUV422 输入时的 Y 分量；输出到显示屏的格式为 RGB565。
e. 帧中断：检测到一帧开始或一帧图像传输完成时可向 CPU 发送中断。

2. 采集显示链路

理解要点：DVP 的"同时输出到 KPU 与显示屏"特性非常关键——同一帧图像既能给 AI 模块做识别，又能给人看，这正是后续图像识别项目的基础架构。

dvp_set_xclk_rate设置输入时钟的速率

2. 实验原理：透镜成像

ov2640 摄像头模组利用透镜成像的原理采集图像：通过感光芯片及相关电路来记录和传输图像信号，按一定的分辨率，以隔行扫描的方式采集图像上的点；当扫描到某点时，就通过图像传感芯片将该点处图像的灰度转换成灰度一一对应的电压值，然后将此电压值通过视频信号端输出。

记忆锚点："光 → 电"：感光点把明暗（灰度）变成电压，扫描逐点输出，再经 DVP 组装成一帧帧图像。

pin_config.h 与 main.c 解析

约 20 分钟

1. pin_config.h 配置（摄像头部分）

DVP 摄像头共有 8 个引脚：像素时钟、输入时钟、行/场同步、电源控制、复位、SCCB 配置（SCL/SDA），全部通过 FPIOA 映射到 IO40~IO47。

// camera（DVP 接口引脚）
#define PIN_DVP_PCLK           (47)
#define PIN_DVP_XCLK           (46)
#define PIN_DVP_HSYNC          (45)
#define PIN_DVP_PWDN           (44)
#define PIN_DVP_VSYNC          (43)
#define PIN_DVP_RST            (42)
#define PIN_DVP_SCL            (41)
#define PIN_DVP_SDA            (40)
硬件引脚IO功能（FUNC）
PIN_DVP_SCL / SDA41 / 40FUNC_SCCB_SCLK / SDA——SCCB 配置总线
PIN_DVP_VSYNC / HSYNC43 / 45FUNC_CMOS_VSYNC / HREF——场/行同步
PIN_DVP_PCLK / XCLK47 / 46FUNC_CMOS_PCLK / XCLK——像素时钟/输入时钟
PIN_DVP_RST / PWDN42 / 44FUNC_CMOS_RST / PWDN——复位/掉电

2. main.c 完整源码

#include "unistd.h"
#include "gpiohs.h"
#include "lcd.h"
#include "st7789.h"
#include "sysctl.h"
#include "uarths.h"
#include "ov2640.h"
#include "dvp_cam.h"
#include "pin_config.h"

extern const unsigned char gImage_logo[153608];

/**
* @brief 设置摄像头和显示器电源域电压值（1.8V）
*/
void io_set_power(void)
{
    sysctl_set_power_mode(SYSCTL_POWER_BANK6, SYSCTL_POWER_V18);
    sysctl_set_power_mode(SYSCTL_POWER_BANK7, SYSCTL_POWER_V18);
}

/**
* @brief 硬件初始化，绑定GPIO口
*/
void hardware_init(void)
{
    /* lcd */
    fpioa_set_function(PIN_LCD_CS,  FUNC_LCD_CS);
    fpioa_set_function(PIN_LCD_RST, FUNC_LCD_RST);
    fpioa_set_function(PIN_LCD_RS,  FUNC_LCD_RS);
    fpioa_set_function(PIN_LCD_WR,  FUNC_LCD_WR);

    /* DVP camera */
    fpioa_set_function(PIN_DVP_RST,   FUNC_CMOS_RST);
    fpioa_set_function(PIN_DVP_PWDN,  FUNC_CMOS_PWDN);
    fpioa_set_function(PIN_DVP_XCLK,  FUNC_CMOS_XCLK);
    fpioa_set_function(PIN_DVP_VSYNC, FUNC_CMOS_VSYNC);
    fpioa_set_function(PIN_DVP_HSYNC, FUNC_CMOS_HREF);
    fpioa_set_function(PIN_DVP_PCLK,  FUNC_CMOS_PCLK);
    fpioa_set_function(PIN_DVP_SCL,   FUNC_SCCB_SCLK);
    fpioa_set_function(PIN_DVP_SDA,   FUNC_SCCB_SDA);

    /* 使能SPI0和DVP */
    sysctl_set_spi0_dvp_data(1);
}

/**
* @brief 主函数，程序的入口
*/
int main(void)
{
    /* 硬件引脚初始化 */
    hardware_init();

    /* 设置IO口电压（摄像头与LCD都需1.8V） */
    io_set_power();

    /* 设置系统时钟和DVP时钟 */
    sysctl_pll_set_freq(SYSCTL_PLL0, 800000000UL);
    sysctl_pll_set_freq(SYSCTL_PLL1, 300000000UL);
    sysctl_pll_set_freq(SYSCTL_PLL2, 45158400UL);
    uarths_init();

    /* 系统中断初始化，使能全局中断 */
    plic_init();
    sysctl_enable_irq();

    /* 初始化LCD */
    lcd_init();

    /* LCD显示图片与欢迎语（1秒） */
    uint16_t *img = &gImage_logo;
    lcd_draw_picture_half(0, 0, 320, 240, img);
    lcd_draw_string(16, 40, "Hello HNSW!", RED);
    lcd_draw_string(16, 60, "Nice to meet you!", BLUE);
    sleep(1);

    /* 初始化摄像头（内部：DVP初始化 + 中断配置 + OV2640寄存器） */
    ov2640_init();

    while (1)
    {
        /* 等待摄像头采集结束，然后清除结束标志 */
        while (g_dvp_finish_flag == 0)
            ;
        g_dvp_finish_flag = 0;

        /* 显示画面 */
        lcd_draw_picture(0, 0, 320, 240, display_buf_addr);
    }

    return 0;
}

3. 主流程解读

硬件与电源：hardware_init() 映射 LCD 与 DVP 引脚；io_set_power() 把 bank6 与 bank7 都设为 1.8V（摄像头和显示器都需要 1.8V 电平信号）。
时钟与中断：PLL0 800MHz（主频）、PLL1 300MHz、PLL2 45.1584MHz（DVP 时钟）；plic_init() + sysctl_enable_irq()。
LCD 欢迎界面：lcd_init() → 显示 logo 图片 + 两行欢迎语，停留 1 秒。
初始化摄像头：ov2640_init()——内部依次完成 DVP 初始化、DVP 中断配置、OV2640 寄存器配置。
实时显示循环：while(1) 等待 g_dvp_finish_flag（中断置 1）→ 清零 → lcd_draw_picture 把 display_buf_addr 的画面刷上屏，循环往复。
教材与工程差异：教材通用示例欢迎语为 "Hello Yahboom!"；本工程源码定制为 "Hello HNSW!"，烧录后以工程源码实际显示为准。
知识活页M9-T2-K2

关键代码详解

约 20 分钟

1. DVP 初始化（dvp_cam_init）

配置作用
dvp_init(8)DVP 初始化，设置 SCCB 寄存器长度为 8bit
dvp_set_xclk_rate(24000000)设置输入时钟为 24MHz
dvp_enable_burst()使能突发传输模式
dvp_set_output_enable(AI, 0) + (DISPLAY, 1)关闭 AI 输出、使能显示模式
dvp_set_image_format(DVP_CFG_RGB_FORMAT)设置输出格式为 RGB
dvp_set_image_size(320, 240)设置输出像素大小为 320×240
iomem_malloc(320*240*2)分配显示缓冲（RGB565 一帧 150KB）
dvp_set_display_addr + dvp_config_interrupt + dvp_disable_auto设置显示地址、使能帧开始/结束中断、关闭自动接收

2. 中断回调（on_dvp_irq_cb）

dvp_cam_set_irq() 注册 DVP 中断（优先级 1）并清除中断位；中断回调里做两件事：

帧完成
置 g_dvp_finish_flag=1
/
帧开始
dvp_start_convert() 继续采集
工程思想：中断回调不刷新屏幕（耗时），只置标志；主循环消费标志后调用 lcd_draw_picture 刷新——与模块四"回调里少做事"一脉相承。

3. 摄像头初始化（ov2640_init）

ov2640_init() 内部流程：先 dvp_cam_init()（配置 DVP 通道）→ dvp_cam_set_irq()（注册中断）→ 读 OV2640 ID 校验 → 把 OV2640 的寄存器以及对应的数据逐一发送（具体的寄存器以及功能可以查看硬件资料中的摄像头资料），完成后开始出图。

4. 逐帧刷新原理

K210 显示摄像头画面是通过一帧一帧刷新 LCD 界面来达到动态效果的：帧完成中断 → 标志置 1 → 主循环把缓冲数据刷上屏 → 等待下一帧。每帧 320×240×2 字节 ≈ 150KB，循环足够快，人眼看到的就是连续视频。

实验总结：① K210 开发板板载 dvp 接口可以与兼容 dvp 接口的 ov2640 摄像头连接使用；② K210 开发板显示摄像头画面是通过一帧一帧刷新 LCD 界面来达到动态效果的。

cmake .. -DPROJ=camera -G "MinGW Makefiles"
等待配置完成（看到 "Generating done" 即成功）。
执行编译。
make
输出编译、链接、生成 .bin 的日志（"Built target camera"）即成功。
确认固件。确认 build 目录下存在 camera.bin。
烧录。用 Type-C 数据线连接开发板与电脑，打开 kflash 烧录工具，选择对应的设备（CH340 串口），Firmware 选择 camera.bin，点击 Flash 烧录。
常见报错：camera 工程包含 lcd 子目录与 dvp_cam.c / ov2640.c，务必整个 camera 文件夹复制进 src 目录，且 -DPROJ=camera 拼写正确。

拓展M9-X1

拓展任务：让摄像头更好玩

选做

拓展 1：改分辨率

修改 dvp_cam.h 里的 CAM_WIDTH_PIXEL / CAM_HIGHT_PIXEL（如 160×120），同时把 main.c 的 lcd_draw_picture 参数改为对应尺寸，观察画面清晰度与流畅度变化。

拓展 2：叠加文字信息

在刷新循环里用 lcd_draw_string 叠加一行计数器（帧率）：每刷新一帧计数加 1，显示在画面左上角，体验"视频 + 信息叠加"（类似监控 OSD）。

拓展 3：灰度画面

把 dvp_set_image_format(DVP_CFG_RGB_FORMAT) 改为 YUV 格式，只取 Y 分量显示（Y 即亮度），观察黑白画面效果；思考为什么灰度图数据量更小。

拓展 4：画面特效

在刷新循环前用 lcd_set_area + tft_fill_data 局部遮挡画面的一角（如右下角白色矩形），做一个"画中画/遮挡"效果；或把画面缩小显示在屏幕一角。

拓展 5（进阶）：打开 AI 输出

在 dvp_cam_init 里把 dvp_set_output_enable(DVP_OUTPUT_AI, 0) 改为 1，并思考：同一帧图像同时给 KPU 和显示屏，KPU 拿到的 RGB888 数据如何用于识别？这为后续"摄像头 + 模型"的图像识别项目做了铺垫。

完成标准：至少完成拓展 1–3 中的两个，并在活页空白处记录每种改动的现象；拓展 4–5 可作为小组探究课题。
